# Тесты проекта — без железа

Прошивки проверяются на обычном компьютере: заглушки Arduino API (`stub_uno/`, `stub_esp32/`) компилируют скетчи через g++ и прогоняют сценарии «патруль → захват → поражение → потеря → отказ датчика/радара → восстановление → протокол настройки».

## Запуск всего

```bash
bash tests/run_tests.sh
```

Нужны `g++` и `python3` с пакетами: `pip install opencv-python-headless numpy`.

## Что проверяется

| Тест | Покрытие |
|---|---|
| `stub_uno/main.cpp` + `pvo.ino` | автомат режимов, SLAVE, тревога датчика, EEPROM, G/S/W/D/M |
| `stub_uno/main_a.cpp` + `pvo_a_simple.ino` | упрощённый вариант A целиком |
| `stub_esp32/main32.cpp` + `pvo_esp32.ino` | декодер радара (контрольные байты из протокола), захват по координатам, тревога/восстановление радара, битые кадры, консоль, G/S/W/D/M |
| `test_vision.py` | детектор на синтетике, геометрия наведения, валидация конфига, фотофиксация |
| `test_gui_logic.py` | разбор протокола, сверка имён параметров GUI ↔ прошивки, CSV журнала, демо-турель |
| `test_fusion.py` | вариант D: геометрия поправок V, детектор ярких точек (ИК), дрёма/пробуждение, захват зрением без радара, ограничения и rate-limit |
| `avr/run_scenarios.sh` | **эмулятор ATmega328P**: настоящая прошивка (avr-gcc + ядро Arduino) исполняется по тактам в avr8js — размер во flash/RAM, реальные тайминги, настоящая EEPROM между перезагрузками |

## Эмулятор ATmega328P — прошивка «как на плате»

Тесты на заглушках проверяют логику, но собирают скетч под x86 с ненастоящим Arduino API. Эмулятор идёт дальше: `avr-gcc` собирает прошивку под настоящий ATmega328P (там `int` 16-битный, `F()` живёт в PROGMEM, EEPROM — 1 КБ), а `avr8js` (тот же движок, что у Wokwi) исполняет её по тактам вместе с таймерами, UART и EEPROM. Стенд имитирует HC-SR04 (эхо по TRIG), меряет ШИМ серво и следит за пином лазера.

Установка (один раз):

```bash
sudo apt install gcc-avr avr-libc arduino-core-avr
(cd tests/avr/js && npm install)
```

Запуск всех сценариев (~15 секунд):

```bash
bash tests/avr/run_scenarios.sh
```

Свой прогон:

```bash
bash tests/avr/build_avr.sh pvo.ino                 # сборка + размер прошивки
node tests/avr/js/run_avr.mjs /tmp/avrbuild/firmware.hex \
     --seconds 14 --target-at 40,7 --target-gone 11 \
     --send "S DETECT 80@3" --expect "ЦЕЛЬ ЗАХВАЧЕНА"
```

Текущие размеры (ATmega328P, 32 КБ flash / 2 КБ RAM):

| Прошивка | Flash | RAM |
|---|---|---|
| `pvo_a_simple.ino` | 9 354 Б (28,5%) | 363 Б (17,7%) |
| `pvo.ino` | 14 490 Б (44,2%) | 547 Б (26,7%) |
| `pvo.ino` + DFPlayer | 15 798 Б (48,2%) | 596 Б (29,1%) |

Что эмулятор **не** проверит: механику (люфт, вес, перегрев серво), физику ультразвука и радара, лазер и ИК-подсветку (для него это просто пины), пристрелку варианта D. И ESP32 он не эмулирует — для варианта B удобен браузерный Wokwi.

Оговорка про Servo: в Debian-пакете `arduino-core-avr` библиотеки Servo нет, поэтому в `tests/avr/Servo/` лежит совместимая реализация на Timer1 (50 Гц, 544–2400 мкс) — только для стенда. На плате используется штатная библиотека из Arduino IDE.

## Симулятор турели для GUI (Linux/macOS)

`sim_turret.py` изображает прошивку на виртуальном порту — можно гонять пульт без платы (в самом пульте для этого проще выбрать порт «ДЕМО»):

```bash
socat -d0 pty,raw,echo=0,link=/tmp/ptyA pty,raw,echo=0,link=/tmp/ptyB &
python3 tests/sim_turret.py /tmp/ptyA uno     # или esp32
python3 pvo_gui.py --port /tmp/ptyB --connect
```

## CI на GitHub (по желанию)

Готовый workflow лежит рядом: `github-workflow-tests.yml`. Если выложите проект на GitHub — скопируйте его в `.github/workflows/tests.yml`, и весь стенд будет прогоняться на каждый push.
